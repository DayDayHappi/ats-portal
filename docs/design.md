# ATS Portal 首版设计

## 已确认目标
在用户当前 Ubuntu 上本机部署。沿用 ATS，执行结束后上报结果与日志。按日期和动态模式查看记录、按问题分类、阅读原始日志。界面参考 ReportPortal 的工作台组织；模式名称和数量不得写死。强调可扩展、灵活、高内聚、低耦合。

## 运行边界
本项目是独立接收端和独立 Python 上报工具，不修改既有 ATS 测试模块。默认仅监听 127.0.0.1:8080；服务数据在用户主目录 .local/share/ats-portal，配置在 .config/ats-portal。提供安装、启动及可选用户级 systemd 服务脚本。交付完整源码与单个 ZIP。当前执行环境不是用户的电脑，实际本机安装由用户运行交付命令完成。

## 技术与职责
Python 3.10+、FastAPI/Uvicorn、SQLite（WAL）、本机文件系统、原生 HTML/CSS/JavaScript。无 Node 构建依赖、无 CDN。数据库访问只在 repository；文件路径/校验/按行读取只在 storage；领域模型与 ATS JSON 适配独立；分类器只消费规范化结果及可配置规则；ingestion 协调生命周期；HTTP 层负责输入、认证与响应；前端只使用版本化 API。

## 上传协议 v1
POST /api/v1/runs 提交 manifest：schema_version=1、run_id、mode{id,name}、started_at（含时区）、ended_at（可空）、execution_state（completed/aborted/unknown）、source（主机/设备/固件可选）、artifacts[{name,size,sha256,kind}]。所有文件名为安全 basename，最多 100 个，单文件上限默认 512 MiB，总上限 2 GiB，可配置。模式 id 是任意非空字符串，不是枚举。report 类型文件最多一个，原样保存。

PUT /api/v1/runs/{id}/artifacts/{name} 流式上传指定文件，检查字节数和 SHA256，临时文件写完原子替换。POST .../finalize 确认全部文件齐全后，读取 ATS report，规范化、分类，一次数据库事务提交结果。重复 manifest 同内容返回原记录；同 run_id 不同 manifest 返回409；文件和 finalize 可重复。未完成上传显示 receiving，不计入已完成结果。未知 schema 拒绝，模式未知允许。原始文件不可被后续重传改写。

## 结果和问题
ATS 的 PASS/FAIL/ERROR/SKIP 保留不变；运行结束状态独立。没有结果不得推断通过。result.json 的 summary 不作为真值，统计来自 results。现有关键字命中仍可为 PASS。默认规则从 JSON 配置加载，采用字面匹配避免不受控正则；支持自定义类别 id/名称和关键字，规则版本记录在运行中。分类来源包括用例失败、命中详情、recovery_events、人工 problem 文件。未知失败有兜底类别。第一版不对全部大日志自动根因分析；日志全文搜索按需进行。问题有结果索引/轮次/次数/命中文本；没有可靠日志行号时只提供搜索，不伪造精确定位。

## 展示和存储
日期按 started_at 转 Asia/Shanghai（可配置）的开始日归档。跨午夜/延迟上传保持同一 run。模式筛选从数据库动态生成。首页运行列表含过滤、分页、汇总、完整性；详情含测试结果、问题与日志。日志读取和搜索都分批、限制返回行数/单行显示长度；下载字节不变。结构化数据在 SQLite，文件存在 artifacts/{run_id}/，与源码分离。新 schema 用迁移版本升级，不删除历史。

原始日志阅读区支持连续双向滚动与窗口展开。前端读取批次300行、保留窗口900行；增删行时保持可见行的屏幕位置，上滚时重新读取较早内容。读取代次隔离文件/查询切换后的迟到响应；暂时失败保留已读内容并提供重试。搜索游标独立保留。实现复用现有按行 API，不改变原始文件与后端存储协议。

用例结果由独立的前端 results.js 汇总，按场景与实际 cycle 分组，默认优先显示有问题的轮次。测试项按（场景、模块、结果名称）合并，编号为各场景中首次出现的顺序；rep 仅作为重复次数。现有报告不包含 YAML task ID/序号，不能将该展示编号解释成配置项序号，也不能可靠区分同模块同名称的不同配置项。每条执行记录及恢复后重跑记录保留，问题通过 result_index 精确关联；无索引的问题单独提示，不猜测归属。展开视图仍显示 ATS 原判定、完整记录和关联日志入口。缺失轮次单独展示，缺失测试项不补 PASS。

## 上报工具

仅标准库，读取现有 ATS 日志目录及报告路径，自动匹配通常的 scenario/date/run_ts 结构，亦支持显式覆盖。首次打包生成持久 run_id，保存不可变副本到本机 outbox；网络失败返回待补传，retry 复用相同 manifest。无需修改 ATS 即可由包装命令运行 ATS 后上报，保留 ATS 原始退出码。正常完成/异常中止、缺报告均有明确语义；用户可独立上传历史记录。

## 本机访问
页面和读接口默认依赖本机绑定；上传必须专用 token。可配置统一读取 token，浏览器使用 HttpOnly/SameSite 会话。无跨域开放，写接口拒绝跨源浏览器请求；使用 bearer 的脚本不依赖浏览器登录。主机与 Origin 校验用于防止本机服务的 DNS rebinding。不会自动对局域网或公网开放。

## 验收
新模式无需改代码；PASS+错误串可发现；重传无重复；错误校验和不入库；缺文件无法 finalize；跨日归档正确；重启后记录/文件存在；下载字节一致；分页/搜索/XSS文本安全；离线 outbox 可补传；包装器不吞 ATS 退出码；浏览器桌面/移动布局可读。
