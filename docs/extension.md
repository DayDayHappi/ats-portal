# 扩展边界

| 模块 | 单一职责 | 典型变化 |
| --- | --- | --- |
| `models.py` | 版本化输入契约和校验 | 新协议字段，保留 v1 兼容 |
| `adapter.py` | ATS JSON 规范化、结果汇总 | 新 ATS 报告格式 |
| `classifier.py` + `config/rules.json` | 独立问题分类 | 新错误串与类别 |
| `repository.py` | SQLite 事务、查询和迁移 | 索引或数据库后端 |
| `storage.py` | 原始字节存储和文本视图 | 稀疏行索引或对象存储 |
| `service.py` | 归档用例编排 | 后台解析任务 |
| `web.py` | HTTP 路由和访问边界 | API 版本、认证方式 |
| `static/` | 浏览工作台 | 交互和可视化 |
| `tools/ats_upload.py` | 独立采集、队列和发送 | 新 ATS 目录布局 |

模式不会出现在业务分支判断中。上传者传稳定 ID 和显示名称，筛选项来自数据库。无需为新模式新增路由、表或组件。

新增关键词分类：复制 `config/rules.json` 里的规则项，提供唯一 `id`、`name`、`keywords`，可用 `statuses` 限定状态。不写 `statuses` 就对所有结果状态匹配。使用字面匹配，避免用户正则造成卡死。规则只影响随后完成归档的运行；已有归档保留当时分类和规则版本。修改规则时也修改顶层 `version`，重启服务生效；历史重分类尚未提供。

所有原始文件保持不变。适配器未识别的原始 JSON 字段仍可从原始报告下载获得。规范化后的状态可能为 UNKNOWN，UI 保留源状态文本。增加新 adapter 时，应先用真实的脱敏报告添加契约测试，再改变映射。

SQLite 使用 WAL 和事务提交。表结构由 `PRAGMA user_version` 管理；新迁移须明确升级路径并先备份。当前无自动降级。大规模运行可替换 repository，巨量日志可给 storage 加行偏移索引，实时上报应增加独立 API，避免改变现有“结束后归档”的一致性语义。
